## 三、方向详述

### 方向 1 · 高铁 / 火车查询
- **背景**：12306 **没有官方 API / MCP**，且涉及实名、支付、风控，**真实订票不现实**。
- **可行的做法**——做「查车次」而非「订票」：
  - **A. 第三方车次查询 API**（如聚合数据等，需申请 key）——稳定、合规。
  - **B. 社区 12306 查询 MCP**（非官方）——能用但有稳定性 / 合规风险。
  - **C. 公开时刻表数据**自建查询工具。
- **建议**：做成查询工具（自定义 Tool 或第三方 MCP），界面明确「仅查询」，订票引导跳转 12306 官方。
- **工作量**：中（取决于数据源选型）。

### 方向 2 · 前端可视化
- 把工具结果**可视化**，而不只是文字：
  - **地图标点**：酒店 / POI 在地图上显示（需引入**高德 JS API** + 对应 key）。
  - **路线绘制**：路径规划结果画线（步行 / 驾车 / 公交）。
  - **工具调用链可视化**：当前仅文字提示「调用了 xx 工具」，可做成流程/时间线展示。
- 其他：语音输入 / 输出、移动端适配。
- **工作量**：中；依赖高德 JS API key。

### 方向 3 · 部署上线
- **目标**：公网可访问，让别人也能用。
- **选项**：
  - **Docker 容器化 + 云服务器**（阿里云 / 腾讯云）。
  - **PaaS**（Railway / Render / Fly.io 等）。
  - **内网穿透**（仅演示：ngrok / cpolar / frp）。
- **注意事项**：
  - **密钥安全**：高德 / DeepSeek key 只在后端，前端经后端代理，绝不暴露。
  - 限流、CORS、HTTPS。
- **工作量**：小–中。

### 方向 4 · 记忆调优
- **LLM 重排**：召回后用 LLM 二次排序，提升相关性（成本权衡，默认关）。
- **更强的中文 embedding**：对比 `bge-m3` 等，提升中文语义召回。
- **遗忘策略调优**：分层 tau、阈值，平衡「记住」与「容量」。
- **召回评估集**：已有 `evaluate_recall`，可扩充为回归测试套件，量化每次改动对召回质量的影响。
- **记忆去重 / 冲突消解**：语义相同的事实自动合并，矛盾事实择优。
- **工作量**：中。

### 方向 5 · 更多 MCP 服务（扩展 Agent 能力）
- 框架已就绪（`MCPToolServer` 可插拔），**接新服务 = 加配置 + key**：
  - 航班 / 酒店（商业 API 或 MCP）。
  - 餐饮（其实高德 POI 已能覆盖大部分）。
  - 日历 / 提醒、网页搜索、天气增强等。
- 每个服务需各自的 key / MCP 端点。
- **工作量**：小–中 / 个。

### 方向 6 · 工程增强
- **多用户隔离**：`namespace` 已预留，但需登录 / 鉴权。
- **持久化存储**：默认演示用进程内存储（重启清空）；生产切 SQLite 文件 + Chroma / PGVector。
- **流式输出**：SSE 流式返回，对话逐字显示，体验更好。
- **异步巩固**：后台定时任务做蒸馏 / 遗忘，而非每轮同步。
- **监控 / 日志**：调用量、成本、错误率。
- **工作量**：中。

## 四、建议推进顺序

1. **先玩起来**：双击 `start.bat`，体验记忆 + 对话 + 地图，找到真实痛点。
2. **看用途选下一步**：
   - 偏**演示 / 展示** → 方向 2（可视化，最出效果）。
   - 偏**实际使用 / 给别人用** → 方向 3（部署）+ 方向 6（持久化）。
3. **出行场景刚需** → 方向 1（高铁查询）。
4. **长期打磨** → 方向 4（记忆调优）、方向 5（更多服务）。

## 五、技术债 / 已知限制

- 高铁 / 订票：12306 无官方接口，仅能做查询（见方向 1）。
- 默认演示后端为进程内存储，重启即清空（生产需切持久化，见方向 6）。
- LLM 回复可能带 emoji / 格式因模型而异。
- `deepseek-v4-flash` 工具调用效果依赖该模型能力，必要时可换更强模型。
