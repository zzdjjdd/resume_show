          01 · 数据模型

          四层记忆，各司其职

          借鉴认知科学：有的记忆只活一个会话，有的要陪用户一辈子。每一层有不同的存储、不同的衰减速度。

          01

          工作记忆

          Working Memory

          当前会话的活跃上下文。滑动窗口 + token 预算，会话结束即释放——短期的"脑子"。

          例：最近 5 轮对话
          02

          情景记忆

          Episodic Memory

          "何时何地发生了什么"。每条带时间戳与重要性，越常被召回越牢固，久了会衰减。

          例：8/1 · 重构了登录模块 · importance 0.8
          03

          语义记忆

          Semantic Memory

          从无数次对话里提炼出的稳定事实与偏好，高度持久、可溯源到原始情景。

          例：用户偏好深色主题 · confidence 0.9
          04

          程序记忆

          Procedural Memory

          "如何做某事"的技能与流程。成功一次就强化，失败就降权——越用越熟练。

          例：部署前先跑测试 → 构建 → 灰度
          02 · 生命周期

          一条记忆的一生

          记忆不是存了就完事——它会被巩固、被反复召回、也会因不重要而被遗忘。

          STEP 1

          写入

          对话进入工作记忆，重要的事件被打上重要性分数，落到情景层。

          STEP 2

          巩固

          后台把情景里的稳定事实蒸馏成语义记忆，把重复的流程固化成程序记忆。

          STEP 3

          检索

          向量语义召回 + 结构化过滤，RRF 融合打分，把最相关的记忆注入当前上下文。

          STEP 4

          遗忘

          强度 = 重要性 × 时近性 × 访问频率。低强度记忆被淘汰，把容量留给要紧的事。

          04 · API

          三行代码，
          开始记忆

          真实 API，来自已完成的 M0–M4。换个 embedder 只需改一个配置项。

          回到控制台玩玩 ↑
          quickstart.py 
          from memoria import Config, Memory

mem = Memory(Config(namespace="user:123"))
mem.init_db()

# 短期：滑动窗口工作记忆
mem.working.append("user", "我喜欢深色主题")

# 长期：情景记忆 + 向量检索
mem.remember_event("用户说喜欢深色主题", importance=0.8)
hits = mem.recall("用户喜欢什么主题?")

print(hits[0].content, hits[0].score)
