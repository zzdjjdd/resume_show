# 03 · 配置与安全

## config.json 结构

```json
{
  "llm":  { "api_key": "sk-...", "base_url": "https://...", "model": "MiniMax-M3", "reasoning_split": true },
  "amap": { "sse_url": "https://mcp.../sse", "api_key": "高德 Web 服务 Key" },
  "mcp":  {
    "servers": [
      { "name": "12306", "url": "https://.../sse", "enabled": true },
      { "name": "hotel",  "url": "https://.../sse", "enabled": true }
    ]
  }
}
```

- **空 `api_key` + 空 `base_url`** → `OpenAI()` 不带参数，读环境变量（`OPENAI_API_KEY` / `OPENAI_BASE_URL`）。
- `reasoning_split=true` → 调 LLM 时附带 `extra_body={"reasoning_split": True}`。
- `config.json` 由前端设置页写入，**仅本机使用**。

## 硬规则

1. **配置不要走 git**：`backend/config.json` 含真实 API Key，`.gitignore` 必须忽略它；
   提交时只保留 `config.py` 中的 `DEFAULT_CONFIG`（空值）。如要纳入 git，必须以
   `config.example.json` 提供模板。
2. **不要回显 api_key**：`GET /api/config` 直接返回整个 `config.json`（前端需要回填表单），
   但**不要**在日志或错误信息里打印 api_key 明文。
3. **`config.json` 是用户数据，不是代码**：改默认值要改 `config.py` 的 `DEFAULT_CONFIG`，
   不要把 `config.json` 当代码改。
4. **不要硬编码 MCP server URL**：它属于用户运行时数据，与 amap 的 `sse_url` 一视同仁。

## 配置 IO 边界

- `config.py` 是**唯一**允许写 `config.json` 的模块。
