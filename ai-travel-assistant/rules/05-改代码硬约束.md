# 05 · 改代码硬约束

## 模块职责切分（不要越界）

- **`main.py`**：HTTP 边缘，只做参数校验、调用 ai_service、把生成器包成 `StreamingResponse`。
  **不要**在这里写业务逻辑或工具逻辑。
- **`ai_service.py`**：唯一允许调用 OpenAI SDK / 编排 ReAct 循环的模块。所有 LLM 相关约定
  （事件、step 名、prompt、extra_body）都在这里定义。
- **`amap_service.py`**：纯函数式封装，唯一允许 `import requests` 去打高德 REST 的模块。
  `MCP_TOOLS` 是给 OpenAI `tools=` 参数用的 JSON Schema 列表。
- **`mcp_client.py`**：唯一允许直连外部 MCP upstream SSE 的模块（见 04-MCP规则.md）。
- **`config.py`**：配置 IO，唯一允许写 `config.json` 的地方。

## OpenAI 客户端

`ai_service._client()` 始终显式传入 `http_client=httpx.Client(...)`，**不要**用默认构造——
openai 1.13.3 内部会传已废弃的 `proxies=` 给 httpx 0.28+，会报错。

## 新增本地 amap 工具：三处必改

同时改以下三处，缺一不可：

1. `amap_service.py`（实现 + 加入 `MCP_TOOLS`）
2. `ai_service.py` 的 `_summarize_tool_result`（加分支）
3. `_summarize_tool_result` 的中文摘要模板

如有新参数类型，则在 `TravelRequest` / `ChatMessage` 上扩展。

## 新增外部 MCP 工具

**无需**改任何 Python 文件（见 04-MCP规则.md）。

## Pydantic 模型

Pydantic 模型在 `main.py` 顶部；新接口加 schema 时保持中文注释风格。

## 修改流程

1. **改业务前**先读 `backend/ai_service.py` 顶部模块注释，记住事件协议。
2. **改前端前**先 grep `event.type` / `case 'step'` 看现有事件消费点。
3. 一次只动一个层级（后端 API / 前端消费 / LLM 行为），逐项验证。
4. 提交前确认 `backend/config.json` 没被改动（用户数据，不应入库）。

## 协作准则

- 对 LLM 输出格式的假设都要在 `ai_service.SYSTEM_PROMPT` 里有显式约束，**不要**靠猜。
- 新增依赖必须更新 `requirements.txt` 与技术栈表格。
- 回答用户问题时优先用中文，与项目 UI / prompt 风格一致。
